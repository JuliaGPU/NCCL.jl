NCCL.jl

A Julia wrapper for the NVIDIA Collective Communications Library (NCCL).

API

Buffers passed to collective and point-to-point operations must be stored contiguously in memory of the device associated with the communicator: a CuArray, or a contiguous view or reshape of one. Operations temporarily activate that device, and restore the previously active device when they return. They are issued on the stream keyword argument, which defaults to the task-local stream of the communicator's device (CUDACore.stream() while that device is active), and must belong to that device; the per-thread default stream (per_thread_stream()) is not supported. Arguments are validated before calling NCCL: buffers whose lengths don't fit the operation throw a DimensionMismatch, and other invalid arguments (e.g. non-contiguous buffers, mismatched element types, ranks out of range, or partially overlapping buffers) an ArgumentError.

Element types

NCCL natively supports buffers of Int8, UInt8, Int32, UInt32, Int64, UInt64, Float16, Float32, Float64 and BFloat16 (from BFloat16s.jl) elements, which can be used with every operation and reduction operator. Some other element types are passed to NCCL as one of these:

  • complex numbers with Float16, Float32, Float64 or BFloat16 parts are passed as pairs of real numbers. NCCL then reduces the real and imaginary parts separately, which is only correct for + and NCCL.avg: reducing complex numbers with *, max or min throws an ArgumentError.
  • Bools are passed as bytes. They can only be reduced with max (logical or) and min (logical and), since sums and averages of booleans are not booleans.
  • other isbits types (e.g. Int16, Char, tuples or immutable structs) are passed as bytes, and can only be copied: they are supported by data movement operations (Broadcast!, Allgather!, Alltoall!, Gather!, Scatter!, Send and Recv!), but not by reductions. Padding bytes in such values are copied as well.

Other element types, i.e. types that aren't isbits (including isbits unions), and types of size zero (e.g. Nothing), are not supported.

Errors

NCCL.LibNCCL.NCCLError — Type
NCCLError(code::ncclResult_t, [msg::String])

An error returned by a NCCL function. code is the result code, and msg the error message NCCL reported for it (see ncclGetLastError), or an empty string if there is none.

NCCL keeps a single, process-wide last error message, which it only updates when it logs a warning and never clears. msg is therefore only set when that message changed since NCCL.jl last read it, so that an error which NCCL didn't log doesn't repeat the message of an earlier one. As a consequence, msg is empty when NCCL reports the same message twice in a row, and may describe an error raised concurrently by another thread. Set the environment variable NCCL_DEBUG=WARN to see all of NCCL's messages.

Communicators

NCCL.Communicator — Type
NCCL.Communicator

An NCCL communicator: one rank of a group of ranks that perform collective and point-to-point operations together.

Communicators are not destroyed by the garbage collector. Destroying a communicator involves communication with the other ranks, which can block, or deadlock when the ranks don't do so at the same time, so it needs to happen at a well-defined point in the program: call NCCL.destroy (or NCCL.abort after an error) when you are done with it, or use the do-block form of the constructors. A communicator that is never destroyed keeps its resources until the process exits.

After a communicator has been destroyed or aborted, it is closed (see isopen), and using it throws an InvalidStateException. Its NCCL.rank, NCCL.nranks and NCCL.device remain available.

Communicators are always blocking; see NCCL.Config.

NCCL.Communicators — Function
NCCL.Communicators(devices; config=nothing) :: Vector{Communicator}
NCCL.Communicators(f, devices; config=nothing)

Create a communicator with one rank per device in devices, all driven from the current task. Rank i-1 uses devices[i]; the devices must be distinct. devices can contain CuDevices or device ordinals.

config can be an NCCL.Config to configure the communicator. Without it, this uses ncclCommInitAll, otherwise one ncclCommInitRankConfig per device in a group.

Operations on several of these communicators have to be issued in an NCCL.group, or the first one blocks waiting for the others. Destroy the communicators together, with NCCL.destroy(comms), or use the do-block form, which destroys them when f returns, and aborts them if it throws (see NCCL.Communicator).

Examples

NCCL.Communicators(CUDACore.devices()) do comms    NCCL.group() do        for (comm, buf) in zip(comms, bufs)            NCCL.Allreduce!(buf, +, comm)        end    endend

NCCL.UniqueID — Type
NCCL.UniqueID()
NCCL.UniqueID(bytes::AbstractVector{UInt8})

The identifier that all ranks of a communicator pass to Communicator, so that they find each other.

UniqueID() creates a new identifier (ncclGetUniqueId). This is done by one rank, which then has to send it to all other ranks by some other means, e.g. MPI, a socket, or a file. UniqueID is a plain bits type of 128 bytes: Vector{UInt8}(id) returns these bytes, and UniqueID(bytes) reconstructs the identifier from them. It can also be sent as-is with anything that handles bits types, e.g. Serialization or Distributed.

Creating an identifier also starts a bootstrap listener on the creating process, so the rank that creates it has to take part in the communicator.

Examples

if rank == 0    id = NCCL.UniqueID()    write(io, Vector{UInt8}(id))else    id = NCCL.UniqueID(read(io, 128))end

NCCL.Config — Type
NCCL.Config(; kwargs...)

Configuration for creating a communicator, passed as the config keyword argument of Communicator and Communicators. Every option defaults to nothing, which leaves the choice to NCCL (or the corresponding environment variable, which takes precedence over most options).

  • comm_name::String: a name for the communicator, used by NCCL in its logs and profiling.
  • net_name::String: the network module to use, e.g. "IB" or "Socket", or the name of an external network plugin (case-insensitive).
  • cga_cluster_size::Integer: the cooperative group array size of the kernels NCCL launches (0 to 8).
  • min_ctas::Integer, max_ctas::Integer: the minimal and maximal number of CTAs that NCCL should use for each kernel (1 to 32).
  • nvls_ctas::Integer: the total number of CTAs to use for NVLink SHARP kernels.
  • cta_policy::Integer: a bitmask of NCCL.LibNCCL.NCCL_CTA_POLICY_* flags.
  • split_share::Bool: whether communicators split from this one may share its resources.
  • traffic_class::Integer: the traffic class to use for network operations; its meaning depends on the network plugin.
  • collnet_enable::Bool: whether to use IB SHARP.
  • n_channels_per_net_peer::Integer: the number of network channels used for each peer in point-to-point communication.
  • max_p2p_peers::Integer: the maximal number of peers a rank communicates with at the same time using point-to-point communication.
  • graph_usage_mode::Integer: how the communicator is used with CUDA graphs: 0 (no graphs), 1 (one graph) or 2 (multiple graphs, or graphs mixed with regular launches; the default).

See the NCCL documentation for the details of each option. Options that the NCCL library in use doesn't know about are ignored.

Communicators are always created in blocking mode: nonblocking communicators, which require polling for the completion of every NCCL call, are not supported yet. NCCL lets the environment variable NCCL_COMM_BLOCKING override this, and also reads that variable from its configuration files (the file named by NCCL_CONF_FILE, or ~/.nccl.conf, and /etc/nccl.conf). Those files only set variables that are not in the environment yet, so when NCCL.jl is loaded, or creates a communicator, while NCCL_COMM_BLOCKING is unset, it sets it to 1, which NCCL's configuration files can then not override. Processes started afterwards inherit this setting. NCCL reads the variable only once per process, so this cannot take effect if another library already initialized NCCL in the process (e.g., by creating a communicator) before NCCL.jl was loaded. If NCCL_COMM_BLOCKING is set to a value that NCCL reads as 0, creating a communicator throws an error. NCCL only parses the leading number of the value (and older versions read a value without digits as 0), so this includes values like 0x0 or 0abc.

NCCL.destroy — Function
NCCL.destroy(comm::Communicator)
NCCL.destroy(comms::AbstractVector{Communicator})

Destroy the communicator comm (or all communicators in comms), after waiting for its outstanding operations to complete. Afterwards, the communicator is closed and can no longer be used. Destroying a closed communicator does nothing.

This first finalizes the communicator (ncclCommFinalize), which flushes its outstanding operations and synchronizes with the other ranks, and then frees its local resources (ncclCommDestroy). Finalization is an intra-node collective operation: all ranks on the same node need to destroy their communicator, or this call blocks. When a task drives several ranks of the same communicator, e.g. the communicators returned by Communicators, destroy them together by passing a vector: their finalization is then grouped, as NCCL requires. Destroying them one by one may deadlock.

If finalization fails, the communicator remains open; use NCCL.abort to free it.

This function must not be called inside NCCL.group.

NCCL.abort — Function
NCCL.abort(comm::Communicator)
NCCL.abort(comms::AbstractVector{Communicator})

Abort the communicator comm (or all communicators in comms): cancel its uncompleted operations and free its resources. Afterwards, the communicator is closed and can no longer be used. Aborting a closed communicator does nothing.

This is meant to release a communicator after an error. It does not wait for outstanding operations or synchronize with the other ranks, but NCCL expects every rank to abort its communicator, and peers that keep using theirs may block. Aborting a communicator is not guaranteed to be able to interrupt an operation that is blocked inside NCCL, because NCCL.jl only supports blocking communicators.

This function must not be called inside NCCL.group.

Groups

NCCL.group — Function
NCCL.group(f)

Evaluate f() as an NCCL group: operations issued by f are only submitted when it returns, which makes it possible to issue a collective on several communicators from a single task, or to combine multiple point-to-point operations without deadlocking.

Groups can be nested; operations are submitted when the outermost group ends.

Because operations in a group are only enqueued on their streams when the outermost group ends, the buffers passed to them must not be read, written, freed, or handed to another task or stream until then. NCCL.jl keeps these buffers, as well as the streams and communicators of the operations, alive until the group ends, so they do not need to be referenced elsewhere. Once the group has ended, the operations are enqueued on their streams, and are ordered like any other work on those streams: the usual CUDA.jl rules for using arrays from other tasks and streams apply.

NCCL keeps track of groups per OS thread, so the following rules apply:

  • The current task is pinned to its thread, and stays pinned after the group ends (the same happens when a task uses @async; tasks created by f may still be running afterwards and rely on it). All operations of the group must be issued from this task; operations issued from other tasks, e.g. Threads.@spawn, are not part of the group.
  • f must not yield to another task that uses NCCL on the same thread. If that happens, the other task's NCCL calls throw a ConcurrencyViolationError rather than silently joining the group.

If f throws, the group is still ended, and the exception thrown by f is rethrown, even if ending the group fails as well. What happens to the operations issued before the exception depends on whether NCCL recorded an error in its group state:

  • NCCL records the errors of operations issued in the group, e.g. when it rejects their arguments. Then the outermost group end discards all queued operations, and submits nothing.
  • Other exceptions don't affect the group, and ending it submits the operations that were issued. This includes Julia exceptions, e.g. from the argument checks of NCCL.jl, which run before NCCL is called, and NCCLErrors from NCCL calls that don't record their errors in the group, e.g. when creating an NCCL.UniqueID. If peers wait for operations that were never issued, this may deadlock.

Communicators are blocking, so ending the group can block, e.g. until the peers have issued their matching operations, before the exception reaches any handler in the caller. Recovering from such a failure, e.g. by having all ranks call NCCL.abort, therefore has to be arranged out of band for the whole job, and can't rely on the failing task. Aborting a blocking communicator is not guaranteed to interrupt a call that is blocked inside NCCL, so terminating the job is the only reliable way out of a hang.

Examples

NCCL.group() do    for (comm, sendbuf, recvbuf) in zip(comms, sendbufs, recvbufs)        NCCL.Allreduce!(sendbuf, recvbuf, +, comm)    endend

Collective communication

NCCL.Allreduce! — Function
NCCL.Allreduce!(sendbuf, recvbuf, op, comm::Communicator;
                stream::Union{CuStream,Nothing} = nothing)
NCCL.Allreduce!(sendrecvbuf, op, comm::Communicator; stream)

Reduce sendbuf over all ranks using op (one of +, *, min, max, or NCCL.avg), and write the result to recvbuf on all ranks. Returns recvbuf. Complex numbers can only be reduced with + and NCCL.avg, and Bools with max (logical or) and min (logical and).

sendbuf and recvbuf must have the same element type and length. With a single buffer sendrecvbuf, the operation is performed in place.

The buffers must be stored contiguously in memory of the device of comm: a CuArray, or a contiguous view or reshape of one. The operation is enqueued on stream, which defaults to the task's stream on that device, and is ordered like other work on that stream. Inside an NCCL.group, it is only enqueued when the group ends, and its buffers must not be used until then.

NCCL.Allgather! — Function
NCCL.Allgather!(sendbuf, recvbuf, comm::Communicator;
                stream::Union{CuStream,Nothing} = nothing)
NCCL.Allgather!(recvbuf, comm::Communicator; stream)

Concatenate sendbuf from each rank, in rank order, into recvbuf on all ranks. Returns recvbuf.

sendbuf and recvbuf must have the same element type, and recvbuf must have nranks(comm) times as many elements as sendbuf. The operation is performed in place when sendbuf is the part of recvbuf that receives the data of this rank. With only recvbuf, that part is sent: recvbuf then consists of nranks(comm) blocks of equal length, and on rank i (counting from 0) the i-th block holds the data to send.

The buffers must be stored contiguously in memory of the device of comm: a CuArray, or a contiguous view or reshape of one. The operation is enqueued on stream, which defaults to the task's stream on that device, and is ordered like other work on that stream. Inside an NCCL.group, it is only enqueued when the group ends, and its buffers must not be used until then.

NCCL.Alltoall! — Function
NCCL.Alltoall!(sendbuf, recvbuf, comm::Communicator;
               stream::Union{CuStream,Nothing} = nothing)

Exchange blocks of data between all ranks: sendbuf and recvbuf are divided into nranks(comm) blocks of equal length, and the j-th block of sendbuf on rank i is copied to the i-th block of recvbuf on rank j (counting from 0). Returns recvbuf.

sendbuf and recvbuf must have the same element type and length, which must be a multiple of nranks(comm). The operation cannot be performed in place: the buffers must not overlap.

The buffers must be stored contiguously in memory of the device of comm: a CuArray, or a contiguous view or reshape of one. The operation is enqueued on stream, which defaults to the task's stream on that device, and is ordered like other work on that stream. Inside an NCCL.group, it is only enqueued when the group ends, and its buffers must not be used until then.
